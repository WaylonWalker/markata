# Markata v0.15.0

Markata v0.15.0 was tagged and its GitHub release published. The successful release run produced **35 expected, nonempty release assets** (16 platform archives, 16 SBOMs, checksums, signature and certificate), according to the [post-release verification in #1885](https://github.com/WaylonWalker/markata/pull/1885). A duplicate tag/dispatch publishing race was later addressed by #1885; its verification concluded that v0.15.0 did not need rereleasing.

**Documentation provenance:** this page is a *post-release documentation correction*, not part of the immutable v0.15.0 tag itself. Highlights below describe changes included during the v0.14.0 → v0.15.0 development cycle; they do not imply that open PRs or work merged after the v0.15.0 tag shipped in that release.

## Highlights

### Markata rendering beyond the site builder

- **Python and FastAPI:** `markata.render()` and `render_async()` expose Markdown rendering with HTML, feature signals and ordered CSS/JS assets, including a document helper for inline assets. The [Python renderer work](https://github.com/WaylonWalker/markata/pull/1835) is merged.
- **Go workbench:** A local Markdown editing and live-preview workbench runs against the native Go renderer ([#1851](https://github.com/WaylonWalker/markata/pull/1851)).
- **Browser WASM:** An offline-capable Markdown workbench runs Markata in a browser worker, without a rendering service ([#1852](https://github.com/WaylonWalker/markata/pull/1852)).
- **Consistent editing:** The three editor demos share major appearance, import/export and save-feedback behavior, plus a custom Markdown command palette ([#1864](https://github.com/WaylonWalker/markata/pull/1864), [#1868](https://github.com/WaylonWalker/markata/pull/1868)). The rendering backends still have documented differences in security policy, offline operation and asset delivery.
- **Editor LSP:** Python and Go browser editors now connect to Markata LSP for context-aware command, Markdown container and Mermaid completions. Browser endpoints enforce loopback peer checks ([#1873](https://github.com/WaylonWalker/markata/pull/1873)).

### Rich Markdown and visual storytelling

- Native Markdown presentation primitives expanded: sortable tables, responsive diagrams/tables, status pills and metrics, accessible gauges, icon cards, task checklists, embedded rendered/source examples and lazy code-copy controls ([#1748](https://github.com/WaylonWalker/markata/pull/1748), [#1752](https://github.com/WaylonWalker/markata/pull/1752), [#1753](https://github.com/WaylonWalker/markata/pull/1753), [#1758](https://github.com/WaylonWalker/markata/pull/1758), [#1763](https://github.com/WaylonWalker/markata/pull/1763), [#1764](https://github.com/WaylonWalker/markata/pull/1764), [#1768](https://github.com/WaylonWalker/markata/pull/1768)).
- Charts gained an accessible static data fallback, improved simple-bar defaults and figure/disclosure options ([#1762](https://github.com/WaylonWalker/markata/pull/1762), [#1812](https://github.com/WaylonWalker/markata/pull/1812), [#1836](https://github.com/WaylonWalker/markata/pull/1836)).
- Road timelines and story layouts gained richer composition, responsive spacing and overlap fixes ([#1744](https://github.com/WaylonWalker/markata/pull/1744), [#1757](https://github.com/WaylonWalker/markata/pull/1757), [#1813](https://github.com/WaylonWalker/markata/pull/1813), [#1814](https://github.com/WaylonWalker/markata/pull/1814), [#1845](https://github.com/WaylonWalker/markata/pull/1845), [#1848](https://github.com/WaylonWalker/markata/pull/1848)).
- Mermaid colors, edges and prerendered contrast were brought closer to the active palette ([#1781](https://github.com/WaylonWalker/markata/pull/1781), [#1785](https://github.com/WaylonWalker/markata/pull/1785), [#1787](https://github.com/WaylonWalker/markata/pull/1787), [#1788](https://github.com/WaylonWalker/markata/pull/1788)).

### CLI, themes and correctness

- A system-font-first default, improved typography hierarchy and shared semantic terminal colors across CLI, forms and TUIs ([#1796](https://github.com/WaylonWalker/markata/pull/1796), [#1823](https://github.com/WaylonWalker/markata/pull/1823), [#1825](https://github.com/WaylonWalker/markata/pull/1825), [#1839](https://github.com/WaylonWalker/markata/pull/1839)).
- Agent setup now detects installed agents and offers a sensible install-all or individual-selection workflow; site-author guidance gained evidence-led visual-post instructions ([#1830](https://github.com/WaylonWalker/markata/pull/1830), [#1841](https://github.com/WaylonWalker/markata/pull/1841)).
- Safer/clearer output for sitemap last-modified timestamps, root-format publishing, standalone series sidebars, Pagefind thumbnail metadata, keyboard shortcuts table semantics and bare-domain Markdown link linting ([#1801](https://github.com/WaylonWalker/markata/pull/1801), [#1842](https://github.com/WaylonWalker/markata/pull/1842), [#1782](https://github.com/WaylonWalker/markata/pull/1782), [#1776](https://github.com/WaylonWalker/markata/pull/1776), [#1777](https://github.com/WaylonWalker/markata/pull/1777), [#1789](https://github.com/WaylonWalker/markata/pull/1789)).
- The legacy shortcuts dialog now remains natively hidden and inert before scripts/styles load, with Chromium coverage for the rendered legacy and embedded templates ([#1853](https://github.com/WaylonWalker/markata/pull/1853)).

## Upgrade and compatibility

This is a **0.x** release, not a declaration of Python-plugin or Go-API compatibility.

- `markata` is the preferred executable; the `markata-go` compatibility binary remains available. Continue to support existing `markata-go.toml`, `[markata-go]` and `MARKATA_GO_*` configuration.
- Current `markata` PyPI releases install the new Go implementation, following the historical Python→Go version break. The `markata` Python renderer API added in this development cycle is a specific new integration, **not** a promise of compatibility with the original Python Markata plugin system. Older versions can be pinned explicitly when needed.
- The WASM editor can reload offline after its assets are available, but that does **not** establish that arbitrary rendered sites make zero outbound requests or that every Mermaid/chart variant is already statically pre-rendered.
- Renderer presets, persistent stdio, warm FastAPI pooling, and unmerged release-automation drafts are **not** part of v0.15.0. Verify later release notes before using these capabilities.

## Release verification and follow-up

- **Tag and GitHub artifacts:** [v0.15.0](https://github.com/WaylonWalker/markata/releases/tag/v0.15.0) exists. The release verification recorded in [#1885](https://github.com/WaylonWalker/markata/pull/1885) found 35 expected nonempty artifacts, including archives, SBOMs, checksums, a signature and certificate.
- **Publication concurrency:** two release triggers raced to publish the same tag. The manual release completed successfully, and [#1885](https://github.com/WaylonWalker/markata/pull/1885), merged after the tag, serialized duplicate runs. It is a post-release workflow fix, not a claim that v0.15.0's tagged source contains that fix.
- **Other distribution channels:** PyPI wheel availability, GHCR image parity, homelab canary/Argo rollout and production browser acceptance are separate verification steps. This document does **not** claim those independently completed.
- **Scope:** unmerged renderer-profile, stdio, warm-pool and automation PRs are excluded from the release claims.

For reproducible source, use the immutable [v0.15.0 tag](https://github.com/WaylonWalker/markata/tree/v0.15.0) and the [v0.14.0...v0.15.0 comparison](https://github.com/WaylonWalker/markata/compare/v0.14.0...v0.15.0). See the [release and rollout runbook](/docs/guides/releasing/) for remaining packaging, canary, acceptance and rollback checks.
